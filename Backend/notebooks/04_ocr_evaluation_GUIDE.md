ในเครื่อง โปรเจกต์ใช้ uv: รัน `uv sync --dev` จากโฟลเดอร์ `Backend` แล้วเลือก kernel `Backend/.venv/Scripts/python.exe` ใน notebook ถ้าเปลี่ยนหรือติดตั้งไลบรารีระหว่างเปิด notebook ให้ Restart Kernel ก่อนรันใหม่ ส่วน Colab ใช้เซลล์ติดตั้งแรกของ notebook

## ต้องมีอะไร

1. ผล OCR แบบ JSONL ของ Typhoon ที่มีอยู่แล้ว
2. ข้อความอ้างอิง (reference) ที่คนตรวจจากภาพ PDF ครบหน้า
3. ถ้าจะเทียบโมเดลอื่น ให้ทำ OCR หน้าเดียวกัน แล้วเก็บใน JSONL รูปแบบเดียวกันอีกไฟล์

ยังไม่มี reference ที่คนตรวจในโปรเจกต์ จึงยังบอกเปอร์เซ็นต์ความถูกต้องจริงไม่ได้

## เริ่มอย่างไร

- เริ่มอังกฤษ 5 หน้า เช่น 1, 10, 20, 36, 39 เก็บหน้า 36 เพื่อดูปัญหาที่พบแล้ว แต่ชุดนี้ไม่ใช่ตัวแทนรับรองทั้งเล่ม
- อ่านภาพ PDF แล้วบันทึก plain text ครบหน้าเป็น `Data/ground_truth/en/page_001.txt` เป็นต้น รวม header และคำบรรยายที่มีจริง ไม่ใส่ Markdown หรือเลขหน้าที่เป็น header/footer
- PDF text layer ช่วยเป็นร่างได้ แต่ต้องตรวจภาพก่อนใช้จริง อย่าคัดลอกผล OCR มาให้คะแนนกับตัวเอง ร่างที่ยังไม่ตรวจเก็บนอกโฟลเดอร์นี้
- เปิด notebook เลือก `LANGUAGE='en'` แล้วรันตามลำดับ ไม่มี reference จะข้ามคะแนนและกราฟ ไม่แสดงศูนย์ปลอม
- ภาษาไทยใช้โฟลเดอร์ `ground_truth/th/` และ `LANGUAGE='th'` วัดแยกภาษา

## Metric ที่ใช้จริง

| Metric | ความหมาย | อ่านอย่างไร |
|---|---|---|
| CER | (แทนที่ + ลบ + เพิ่มตัวอักษร) / จำนวนตัวอักษร reference | ต่ำดีกว่า ใช้ทั้งสองภาษา |
| WER | สูตรเดียวกัน แต่นับเป็นคำโดยแยก whitespace | ต่ำดีกว่า ใช้เพิ่มเฉพาะอังกฤษ |

คะแนนรวมใช้ errors รวม / ความยาว reference รวม ไม่เฉลี่ยเปอร์เซ็นต์รายหน้า CER อาจเกิน 100% และ `1-CER` ไม่ใช่ accuracy ทางความหมาย ไทยนับเป็น Unicode code points หลัง NFC ไม่ใช่จำนวนรูปตัวอักษรที่ตาเห็นเสมอไป

ยังต้องอ่าน diff ของจำนวนเงิน เลขมาตรา วันที่ และคำปฏิเสธด้วย เพราะคำผิดหนึ่งคำอาจเปลี่ยนความหมาย แม้ CER ทั้งหน้าต่ำ เราไม่ต้องเพิ่ม metric ตาราง กราฟ ลำดับบล็อก หรือคะแนนจาก LLM ในรอบนี้

## กติกาเตรียมข้อความ

ใช้ `content_v1` เหมือนกันทุกโมเดล: NFC, ยุบ whitespace, เอาแท็ก `<page_number>…</page_number>` และเครื่องหมายหัวข้อ/emphasis ที่โค้ดรองรับออก เก็บตัวเลข คำปฏิเสธ ตัวพิมพ์ และคำบรรยาย figure ไว้ ตัดเฉพาะตัวครอบ figure เพื่อให้คำบรรยายแต่งขึ้นยังถูกนับเป็น error

นี่เป็นกติกาแบบง่าย ไม่รองรับ Markdown ทุกแบบ หากพบเลขหน้าแบบไม่มีแท็ก หรือ wrapper ใหม่ ให้ตรวจและกำหนดกติกาเพิ่มกับทั้ง reference/prediction อย่างสม่ำเสมอ ห้ามลบตัวเลขทั่วไปหรือแก้คำให้คะแนนดีขึ้นโดยไม่บันทึกไว้

## เทียบโมเดลอื่น

เพิ่มผลของโมเดลที่ลองจริงใน `MODELS` เช่น:

```python
MODELS = {
    'Typhoon': DATA_ROOT / 'jsonl' / 'pdpa_en_typhoon_ocr.jsonl',
    'Model B': DATA_ROOT / 'jsonl' / 'pdpa_en_model_b_ocr.jsonl',
}
```

แต่ละบรรทัดต้องมี `pdf_page`, `text`, `language`, `source_file` โดย `source_file` ต้องเป็นชื่อ PDF เดียวกัน โมเดลใหม่อาจต้องแปลง output ให้อยู่ในรูปแบบนี้ก่อน โค้ดไม่เรียกโมเดลให้ และจะหยุดถ้ามีโมเดลใดขาดหน้า reference แทนการแอบตัดหน้าที่ขาดออกจากคะแนน

ดูตาราง CER/WER และ **กราฟเดียว: CER รายหน้าแยกโมเดล** แล้วเปิด diff ของหน้าที่ผิดเยอะ เลือกจากผลบนหน้าเดียวกัน ไม่ใช่คะแนนโฆษณาคนละชุดข้อมูล บันทึกเวอร์ชันโมเดลและค่าที่ใช้ด้วย

ถ้าเปลี่ยนโมเดลแล้ว CER/WER ลดและแก้จุดผิดสำคัญได้ จึงมีหลักฐานว่าเหมาะกับข้อมูลชุดนี้มากขึ้น ก่อนตัดสินใจรอบสุดท้ายลองหน้าใหม่อีกเล็กน้อยที่ไม่ได้ใช้เลือกโมเดล ยังไม่จำเป็นต้องตั้งระบบแบ่งชุดหรือ annotation workflow เพิ่ม

`SAVE_REPORT=True` จะเก็บ `summary.csv`, `by_page.csv` และ `cer_by_page.png` ในโฟลเดอร์รอบใหม่ ไม่แก้ผล OCR เดิม ค่าเริ่มต้นไม่เขียนรายงาน
