### 3. โหลดโมเดล

```python
processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForImageTextToText.from_pretrained(
    MODEL_ID,
    dtype=torch.float16,
    device_map='auto',
).eval()
prompt = get_prompt('v1.5')('')
```

- `processor` จัดภาพและข้อความให้อยู่ในรูปแบบที่โมเดลรับได้ และแปลงคำตอบกลับเป็นข้อความ
- `model` เป็นตัวอ่านข้อความจากภาพ ดาวน์โหลดมาอยู่ในเครื่อง Colab ไม่ได้เรียก OCR ผ่าน API ในโค้ดนี้
- `float16` ใช้ตัวเลขขนาดเล็กกว่า float32 เพื่อประหยัดหน่วยความจำสำหรับน้ำหนักโมเดล
- `device_map='auto'` ให้ไลบรารีจัดวางโมเดลตามอุปกรณ์และหน่วยความจำที่มี ไม่ได้รับประกันว่าทุกส่วนอยู่บน GPU
- `.eval()` ตั้งโหมดประเมินผล ส่วน `prompt` คือคำสั่งที่บอกโมเดลให้ทำ OCR

### 4. นิยามฟังก์ชัน OCR

**รันเซลล์นี้เพื่อประกาศฟังก์ชัน ยังไม่ได้เริ่มอ่านทั้งไฟล์** มีสองฟังก์ชัน:

| ฟังก์ชัน | ทำอะไร | ผลที่คืน |
|---|---|---|
| `ocr_page(pdf_path, page_number)` | แปลงหนึ่งหน้าเป็นภาพ แล้วอ่านข้อความ | `dict` ข้อมูลหนึ่งหน้า |
| `ocr_file(pdf_path, language)` | เรียก `ocr_page()` ตั้งแต่หน้าแรกถึงหน้าสุดท้าย แล้วเติมข้อมูลอ้างอิง | `list` ของข้อมูลทุกหน้า |

ตัวอย่างส่วนเตรียมภาพจาก `ocr_page()`:

```python
source_image = convert_from_path(
    str(pdf_path), first_page=page_number, last_page=page_number, dpi=150,
)[0]
image = source_image.convert('RGB')
image.thumbnail((1800, 1800), Image.Resampling.LANCZOS)
```

อ่านทีละหน้าเพื่อลดจำนวนภาพที่ต้องเก็บพร้อมกัน ใช้ความละเอียด 150 DPI แล้วลดภาพให้พอดีกรอบ 1800 × 1800 โดยรักษาสัดส่วน การเพิ่มความละเอียดอาจช่วยตัวอักษรเล็ก แต่ใช้ทรัพยากรมากขึ้นและต้องทดลองเทียบผล

จากนั้นเตรียมภาพกับ prompt ผ่าน `apply_chat_template()` ส่งข้อมูลไปอุปกรณ์ของโมเดล เรียก `model.generate()` และใช้ `processor.decode()` แปลงผลเป็นข้อความ

ระหว่างสร้างคำตอบใช้ `torch.inference_mode()` เพื่อลดงานที่เกี่ยวกับการฝึกโมเดล, `do_sample=False` ปิดการสุ่ม และ `repetition_penalty=1.1` ลดแนวโน้มการสร้างข้อความซ้ำ หลังแต่ละหน้าจะปิดภาพ ลบตัวแปรชั่วคราว และคืน GPU cache ที่ไม่ได้ใช้

### 5. OCR ทั้งไฟล์

นี่คือขั้นที่ใช้เวลาอ่านจริง รอจนเห็นข้อความว่าอ่านครบทุกหน้า **ผลยังอยู่ใน RAM ของ Colab และยังไม่มีการบันทึกไฟล์**

ถ้าหยุดระหว่างทาง โค้ดปัจจุบันไม่มี checkpoint หรือการทำต่อจากหน้าที่ค้าง ผลบางหน้าภายใน `ocr_file()` จะยังไม่ถูกส่งกลับเข้า `results` ภายนอก ต้องรัน OCR ใหม่เมื่อผลไม่ครบ เช่นเดียวกับกรณี runtime ถูกรีเซ็ตก่อนบันทึก

### 6. ตรวจข้อความก่อนบันทึก

```python
PREVIEW_PAGE = 1
```

ตัวอย่างนี้ย่อจากเซลล์จริง ซึ่งตรวจว่าจำนวนผลครบก่อนแสดงข้อความ เปลี่ยน `PREVIEW_PAGE` เพื่อดูหน้าอื่น หน้า PDF เริ่มที่ 1 แต่ตำแหน่งใน list เริ่มที่ 0 จึงต้องลบ 1

เทียบกับ PDF อย่างน้อยหน้าแรก หน้าที่มีมาตรายาว และหน้าท้าย ตรวจตัวอักษร เลขมาตรา ลำดับข้อความ และส่วนที่หาย โดยเฉพาะคำบรรยายใน `<figure>` ซึ่งโมเดลอาจแต่งขึ้น

## ข้อมูลใน JSONL หนึ่งรายการ

ตัวอย่างสมมติ เพื่อแสดงโครงสร้าง ไม่ใช่ผล OCR จริง:

```json
{"pdf_page":1,"text":"ข้อความที่อ่านได้จากหน้านี้","elapsed_seconds":50.0,"possibly_truncated":false,"language":"th","source_file":"PDPA (TH).pdf","section_or_article":null,"model":"typhoon-ai/typhoon-ocr1.5-2b"}
```

- `pdf_page` คืออันดับหน้าในไฟล์ PDF อาจต่างจากเลขหน้าที่พิมพ์บนเอกสาร
- `text` คือข้อความดิบ อาจมี Markdown หรือแท็กจากโมเดล
- `language`, `source_file`, `pdf_page` เป็นข้อมูลอ้างอิง หรือ **metadata** ใช้ระบุว่าข้อความมาจากไหน
- `elapsed_seconds` คือเวลาประมวลผลหน้านั้น และ `model` ระบุโมเดลที่ใช้
- `section_or_article` ยังเป็น `null` ทุกหน้า เพราะโค้ดยังไม่ได้แยกมาตรา

ไฟล์ JSONL ที่มีหลายหน้าจะมี JSON หลายบรรทัด ไม่ได้ครอบทั้งหมดด้วย `[]` ตัวอย่างอ่านใน Python:

```python
import json
from pathlib import Path

path = Path('/content/drive/MyDrive/PDPA_RAG/Data/jsonl/pdpa_th_typhoon_ocr.jsonl')
with path.open(encoding='utf-8') as file:
    records = [json.loads(line) for line in file if line.strip()]

print(len(records))
print(records[0]['text'][:200])
```

## เปลี่ยนจากภาษาไทยไปอังกฤษอย่างไร

1. ตรวจและบันทึกผลภาษาไทยข้อ 7 ให้เรียบร้อยก่อน
2. ตั้ง `LANGUAGE = 'en'` แล้วรันเซลล์เลือกไฟล์ในข้อ 2 ใหม่ เพื่ออัปเดต `PDF_PATH`, `SAVE_PATH`, `TOTAL_PAGES`
3. ถ้า runtime เดิมยังมีโมเดลและฟังก์ชันอยู่ รันข้อ 5 เพื่อ OCR อังกฤษ แล้วตรวจข้อ 6 และบันทึกข้อ 7
4. ถ้า runtime ถูกรีเซ็ต ให้เริ่มตั้งแต่ข้อ 1

ข้อ 5 จะแทนค่า `results` เดิมใน RAM แต่ไม่ลบไฟล์ภาษาไทยที่บันทึกลง Drive แล้ว อย่าเปลี่ยนภาษาและรันเซลล์เลือกไฟล์ระหว่างที่ OCR รอบเดิมกำลังทำงาน

## เจอปัญหานี้ ให้ตรวจอะไร

| อาการ | วิธีตรวจและแก้ |
|---|---|
| ไม่พบ GPU | เลือก GPU runtime แล้วเชื่อมต่อใหม่ ตรวจด้วย `torch.cuda.is_available()` |
| ไม่พบ PDF | ตรวจชื่อไฟล์ วงเล็บ ตัวพิมพ์ และ path ใน `PDF_FILES` หลังเชื่อม Drive |
| `NameError` เช่น `results` หรือ `model` | รันเซลล์ก่อนหน้าตามลำดับ หาก runtime รีเซ็ตต้องสร้างตัวแปรใหม่ |
| ข้อ 6/7 แจ้งผลไม่ครบ | รอข้อ 5 ให้จบ หากถูกหยุดต้อง OCR ใหม่ โค้ดนี้ยังทำต่อจากหน้าค้างไม่ได้ |
| `FileExistsError` | ใช้ชื่อ `SAVE_PATH` ใหม่ เช่น `_v2` แล้วรันเฉพาะเซลล์บันทึก เมื่อผลใน RAM ยังครบ |
| `apt-get` ใช้ไม่ได้บน Windows | เปิดและรันบน Colab แทนการใช้ Python ในเครื่องกับ notebook นี้ |
| ข้อความแปลก ซ้ำ หรือขาด | เทียบหน้าที่มีปัญหากับ PDF ก่อนปรับค่าหรือใช้ข้อมูลต่อ จำนวนหน้าครบไม่ได้รับรองความถูกต้องของ OCR |

## จะนำไปทำ Embedding ต่ออย่างไร

ใช้ **JSONL เป็นข้อมูลต้นทาง** เพราะมีข้อความพร้อมแหล่งอ้างอิง อ่าน `text` มาตรวจและเตรียมข้อความ จากนั้นแบ่งเป็นส่วนย่อยหรือ **chunk** ตามหัวข้อ/มาตรา แล้วส่งข้อความของแต่ละ chunk ไปสร้าง Embedding ซึ่งเป็นเวกเตอร์ตัวเลขสำหรับค้นหาข้อความที่มีความหมายใกล้กัน

เก็บ metadata เช่น ภาษา ชื่อ PDF และหน้าที่เกี่ยวข้องไว้กับแต่ละ chunk ด้วย เพื่อย้อนกลับไปอ้างอิงเอกสารได้ ขั้นตอนนี้ยังไม่ได้อยู่ใน notebook และหนึ่งหน้า OCR ไม่จำเป็นต้องเท่ากับหนึ่ง chunk หรือหนึ่งมาตรา
